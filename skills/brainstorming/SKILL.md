# Brainstorming

## Process

1. Explore project context (files, docs, recent commits)
2. Ask clarifying questions — one at a time, multiple choice preferred
3. Propose 2-3 approaches with trade-offs
4. Present design sections incrementally, get approval for each
5. Write design document to workspace/{task}/SPEC.md
6. Self-review: check for placeholders, contradictions, scope issues
7. Get human approval before proceeding

## Key Principles

- NEVER write code during brainstorming — this is design only
- One question at a time — don't overwhelm
- Every project goes through this, no matter how simple
- YAGNI ruthlessly — remove unnecessary features

## Output

Generate SPEC.md covering: problem statement, solution approach,
affected components, data model changes, API changes, error handling strategy.
